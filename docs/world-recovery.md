# Static world recovery and verification

`tools/build-world.luau` already rebuilds the base, four plots, pedestals,
Vehicle Bay, Safe Line, all ten stage floors/arches/props, water edges,
neon grid and perimeter walls. It uses Config and previously audited
`ReplicatedStorage.SalvageAssets` templates. It replaces `SalvageWorld`,
so use it only for a requested recovery and only in Edit mode.

`default.project.json` also includes the complete static world and all
113 templates from `assets/snapshot/`. `rojo build default.project.json
-o salvage-run.rbxlx` produces a complete place from those saved assets
and the current `src/` scripts. It does not prove that a cloud place has
been published, and sync must preserve the user's editor-only UIKits.

Execute the repo source of `tools/verify-world.luau` through Studio MCP in
the connected Edit DataModel immediately after every world mutation.
It is read-only and asserts the expected inventory, template sanitation,
Safe Line collider fix, wall collisions and absence of Baseplate. Do not
start/stop a user's playtest to run it. Record its observed result before
marking a world change verified in PROGRESS.md.

There are **26 perimeter walls total**, including **three at Stage 10**:
twenty strip side walls, two base side walls, two entrance shoulders,
the base back wall and the strip end wall. The user confirmed this count.

Mobs, loose loot, hazards, vehicles, owner headshots and Collection displays
are generated by server services during Play. They are not missing static
map pieces when absent in Edit. Verify their behavior in a separately
authorized playtest; never replace them with saved test fixtures.

## Persistence

The custom `src/server/DataService.luau` uses UpdateAsync session locks.
Production store: `SalvageRun_v1`. Studio store: `SalvageRun_v1_Studio`.
The lock lease expires after **180 seconds**, renewed by saves every
**60 seconds**. Load rejects a different session's unexpired lock; an
expired lock is atomically replaced with the new session token while
keeping the saved Data. Save verifies the token so an older session
cannot overwrite a newer owner. Four load attempts wait six seconds
between busy-lock retries; this is not the 180-second lease itself.

Do not force-steal an active lock while the user may be playing. Local
unpublished/API-failed Studio sessions use scratch data and do not write
over persistent records. No playtest was started for this recovery audit.
